# JAPAN APPROACH

日本の空港の進入管制をするレーダーゲームです。HTML + JavaScript + CSS だけで動きます。

**ブラウザで遊ぶ: https://raihun.github.io/ATC-Game/**

マップは 関東 (羽田・成田) / 中部 (セントレア・小牧・静岡) / 中国・四国 (広島・岡山・高松・松山・高知) の3つ。

## 遊び方

上の URL を開くか、このリポジトリをダウンロードして `index.html` をダブルクリックしてブラウザ (Edge / Chrome) で開くだけです。インストールやサーバーは要りません。

1. タイトル画面でマップ・滑走路運用・難易度を選んで「管制開始」
2. 到着機 (黄) を ILS に乗せて着陸させ、出発機 (水色) を離陸させて出口 Fix へ送り出す
3. 一時停止 (入力欄が空のとき Space) しながらじっくり指示してかまいません

### 設定 (右上の ⚙)

- **コンピュータ管制**: 手動 / AUTO の切り替え (下記)。AUTO 中は上部に「AUTO 中」が表示され、押すと設定が開く
- **高度の見せ方**
  - 標準: データブロックの数字だけ
  - 立体 (影): FlightRadar24 のように、機体の右下に柔らかくぼやけた影を落とす。高い機体ほどアイコンが大きく、影は遠く・大きくぼやけて薄い。低い機体は小さく、影はほぼ真下。機体は本当の位置のままなので、間隔の見た目は正しいまま
- **選択中の機体との高度差を表示** (初期設定オン): 機体を選ぶと、他の機体の横に高度差 (百ft 単位、例 `+12` `−05`) を表示。1000ft 未満は赤、2000ft 未満は黄、3000ft 以上離れた機体は薄く表示

表示の設定はゲームをまたいで保存されます。

### コンピュータ管制 (AUTO)

右上の設定で「AUTO」を選ぶと、コンピュータが2秒ごとに状況を見て、普通のコマンドで指示を出します (ログにも読み上げが出ます)。疲れたときに任せたり、お手本として眺めたりできます。設定で「手動」を選ぶと手動に戻ります。

- 出発: 滑走路ごとに 90 秒以上あけ、着陸機が近くにいない時に離陸させる。出口高度まで上昇させ、経路を外れていれば出口 Fix へ向かわせる
- 到着: 同じ列 (平行な滑走路は別々、羽田 22/23 のように進入コースが交わる滑走路は1列) の前の機体と 10NM 以上の差が取れる時だけ進入許可。取れなければ STAR の終点で待機させ、6000ft から 1000ft ずつ積む (下が空いたら1段ずつ降ろす)
- 間隔: 同じ列で 7NM より詰まったら後ろを減速、3NM より詰まったら復行 (ILS に乗る前なら進入許可の取り消し)
- 接近回避: 90 秒先までの位置を予測し、近づきそうな組は上昇・降下を止めるか 1000ft 離す。新しい高度はほかの全機と接近しないものを選び、出発機は降下させない
- 自分のコマンドも併用できる (コンピュータが後で上書きすることはある)
- 一度でも使ったゲームはハイスコアの対象外。AUTO の状態も自動保存される

テスト (各難易度・北風/南風で 2 時間ずつ計 80 時間分) では衝突・逸脱ともに 0、間隔欠如は 2 時間あたり 0.2 回 (ふつう) 〜 3.8 回 (上級) でした。完璧ではないので、混んでくると間隔欠如はたまに起きます。

### 自動保存

ゲームの状態は2秒ごと (とページを閉じる時) にブラウザの localStorage へ自動保存されます。
F5 で再読み込みしたりブラウザを閉じたりしても、次に開くと一時停止した状態で続きから再開します (Space で再開)。

- 機体の位置・高度・速度・経路・待機・進入許可、得点、ログ、地図の表示位置、選択中の機体まで戻ります
- 結果画面に進んだときと、メニューの「タイトルへ戻る」を選んだときは保存を消します
- 保存はブラウザごとです (Edge で遊んだ続きは Chrome では出てきません)

### 難易度

「同時に飛ぶ最大機数」を超えて機体が増えることはありません。最初の10分は出現間隔が長めで、だんだん設定値に近づきます。
スライダーで自由に調整でき、ハイスコアは設定ごとに保存されます。

「実際のピーク」は、そのマップの実際の混み具合に近い設定です (最大機数のスライダーもここまで広がります)。

| マップ | 最大機数 | 出現間隔 | 目安 |
|---|---|---|---|
| 関東 | 40機 | 22秒 | 羽田・成田あわせて1時間に約160回の離着陸。到着は空域に約20分、出発は約10分いるので、同時に約40機 |
| 中部 | 20機 | 60秒 | セントレア・小牧・静岡の離着陸と上空通過で1時間に約60機 |
| 中国・四国 | 20機 | 50秒 | 5空港で1時間に約40回の離着陸と、瀬戸内の上空通過が約30機 |

実際の関東は、この機数を10以上の管制席 (セクター) で分けて担当しています。1人で全部を見るのはかなり大変です。

- 流量制御: 待機中の到着機が滑走路1本あたり2機以上いる空港へは、新しい到着機を出しません。実際も、航空交通管理センターが出発空港で待たせて、空中で待つ機体が増えすぎないようにしています
- コンピュータ管制 (AUTO) は「実際のピーク」でも衝突なしで回りますが、待機の積み重ねの中で間隔欠如がときどき起きます

### コマンド

| 入力 | 意味 |
|---|---|
| `JAL123 L 30` / `R 30` | 左 / 右へ30°旋回 |
| `JAL123 H 270` | 方位270へ (`LH` / `RH` で旋回方向を指定) |
| `JAL123 D 40` / `C 90` | 4000ft へ降下 / 9000ft へ上昇 (`A` でも可。1000未満は百ft単位) |
| `JAL123 S 210` | 速度 210kt |
| `JAL123 CREAM` | CREAM へ直行。経路上の Fix なら、その先は経路どおりに飛ぶ |
| `JAL123 KZE-CREAM` | 経路の付け替え (リルート)。スペース区切りでも可 |
| `JAL123 ILS 34L` | 進入許可。滑走路を省くと予定の滑走路 (`JAL123 ILS`)。LDA の滑走路 (羽田 22/23 の南風・好天) も `ILS 22` で出せます |
| `JAL123 STAR DARKS` | 同じ入口から入る別の標準到着経路 (STAR) に切り替える。滑走路もその STAR のものになる |
| `JAL123 T` | 離陸許可 |
| `JAL123 GA` | 復行 |

- まとめて書けます: `JAL123 D40 S180 CREAM`
- 便名は末尾の数字だけ (`123`) でも、機体を選択中なら省略しても通ります
- Tab で機体を順に選択、Esc で選択解除

### 経路 (飛行計画)

実際の管制と同じく、各機は飛行計画の経路を持っていて、指示がなければその Fix を順に自動で飛びます。

- 到着機: 空域の端に現れ、実在の STAR (例: CREAM ARRIVAL = `STONE-TLE-CURRY-COUPE-CUTIE-CREAM`) を飛ぶ。最後の Fix は許可限界点で、進入許可がないまま着くとそこでホールディング (右旋回・アウトバウンド1分) する
- 進入許可 `ILS 34L`: 経路の残り → FAF → 最終進入コースと自分で飛び、FAF の高度まで自分で降下して着陸する。レーダー誘導中に出すと今の方位のまま会合する。高すぎるなどで乗れなければ進入を中止する
- 混雑時はレーダー誘導で間隔を詰め、空いているときは進入許可で任せる、という実際の使い分けができる
- 進入許可を受けて STAR の最後まで来た機体は、自分で最終進入コースへ回り込む (滑走路の横で終わる STAR でも乗れる)
- STAR の終点 (IAF) から先に進入方式の経路があるもの (羽田 BACON→BIBLO-BEAST-BONDO など) は、進入許可を受けてからその経路を飛ぶ。許可がなければ STAR の終点で待機する
- 出発機: 離陸後に実在の SID (例: JYOGA DEPARTURE) を出口 Fix まで飛ぶ。上昇の指示は必要。経路は滑走路ごとに違う
- ショートカット: `JAL123 COUPE` のように経路上の先の Fix へ直行させると、その先 (`CUTIE-CREAM`) は経路どおり
- レーダー誘導: 方位を指示すると経路から外れる。経路上の Fix 名を指示すれば、そこから経路に戻る
- 経路の付け替え: `JAL123 DENNY-COUPE` のように経路にない Fix を含む並びを指示すると、新しい経路として許可し直す (`CLEARED VIA ...`)
  - 最後の Fix が元の経路上にあれば、その先は元の経路に合流する (例: CREAM ARRIVAL の機体なら `DENNY-COUPE-CUTIE-CREAM` になる)
  - 合流しなければ、最後の Fix が新しい許可限界点になり、進入許可がなければそこでホールディング
  - 出発機は出口 Fix が経路の最後に自動で付く
  - 点線の標準経路から離れるので、航跡ボーナスは下がる
- 経路を一から組み直す: 操作パネルの「組み直す」を押し (または Shift+Fixクリック)、地図の Fix を順にクリックして Enter (または「確定」)
  - 組み立て中は元の経路のまま飛び続け、新しい経路は紫の破線と番号で表示される。確定すると経路をまるごと置き換える (`CLEARED VIA ...`)
  - Backspace で1つ戻す、Esc でやめる。別の機体を選ぶと組み立て中の経路は捨てる
  - 出発機は出口 Fix を入れなくても最後に自動で足す
  - コマンドでは `JAL123 VIA KZE CREAM` で同じことができる
- 操作パネルの「経路」ボタンで、経路上の Fix へワンクリックで直行できる
- 操作パネルの「標準経路」ボタン: 同じ入口から選べる STAR が複数あるとき (例: 南風・好天で ADDUM から入る機体は BACON→22 / BALAN→22 / DARKS→23) に出て、押すと経路と滑走路を切り替える

### マウス

- 機体クリック: 選択。選択した機体のまわりに操作リングが出ます
  - 内側の輪: 方位。マウスを乗せると `L30 → 270` のように旋回量が出て、クリックで近い方へ旋回 (Shift+クリックで遠回り)
  - 右の弧: 高度 (2000〜15000ft、上ほど高い) / 左の弧: 速度 (160〜300kt、上ほど速い)
  - 白い三角が現在値、水色の三角が指示値。押したままなぞって、離した所で決めることもできます
- 選択中に Fix をクリック: 直行 (Shift+クリックで経路の組み直しを始める)
- 右クリック: その方向へ旋回 / ドラッグ: 地図の移動 / ホイール: 拡大縮小

### 着陸 (簡易 ILS)

進入許可を出すのがいちばん簡単です。許可を出さずにレーダー誘導だけで入れる場合は、黄色い扇形の中で、最終進入コースに対して ±60° 以内の向き、かつ進入コース上の黄色い目盛り (百ft単位) 以下の高度にすると自動で ILS を捕捉し、そのまま着陸します。

### LDA 進入 (羽田 22/23・南風・好天)

実際の羽田の南風運用では、22/23 へは ILS でまっすぐではなく、千葉の海岸沿いを西へ進み (LDA コース)、MAPt (進入復行点) から目で見て左へ回り込んで着陸します。FlightRadar24 で見える「千葉から海岸沿いに西へ → 羽田の手前で左旋回」の航跡がこれです。

- 南から: `ADDUM-BLITZ-BRASS-BACON-BIBLO-BEAST-BONDO` → 22 (LDA Z)。湾の上からは `…KAIHO-LD225-LD224-LD223-BALAN-TAYAS` → 22 (LDA Y)
- 北から: `STONE-DREAD-DENNY-DATUM-DELCA-DEANE-DAMBO` → 23 (LDA Z)。湾の上からは `…LD224-DARKS-DOMEL` → 23 (LDA Y)
- 2本の LDA コースは約 2NM 離れた平行なコースなので、22 と 23 は別々の列として同時に進入できます (実際も同時進入が認められています)
- 地図では黄色の実線が LDA コース、MAPt から滑走路までの点線が目視で回り込む部分です。乗り方 (捕捉の条件・速度) は ILS と同じ

### 高度の半円方式 (上空通過機)

巡航中の機体は、進む方向 (磁方位) で使える高度が決まっています。

- 東向き (磁方位 0〜179°): 奇数の高度 (FL170, FL190, FL210…)
- 西向き (磁方位 180〜359°): 偶数の高度 (FL180, FL200, FL220…)

ゲームでは、巡航したまま抜けていく上空通過機 (中部の KANTO / EAST / WEST) の出口高度にこの決まりがあります。方向に合わない高度だとハンドオフできません。操作パネルの高度ボタンは、その機体の向きに合う高度だけを並べます。
進入・出発の機体はレーダー管制下で上昇・降下中なので、この決まりは関係しません (実際も、ターミナル空域では管制官が指示した高度で飛びます)。

### 速度

- 10000ft 未満は 250kt 以下。250kt を超える指示は 250kt になる (10000ft 以上へ上昇中の機体には「ABOVE 10000」として受け付ける)。10000ft 未満へ降りる機体は少し上から減速を始める
- STAR の速度制限 (AIP より): STONE 250kt、ADDUM 230kt、LD225 220kt、MARCH 185kt。その Fix に近づくと自動で守る。速度を指示すると解除される
- ホールディング中は 230kt 以下
- ILS に乗れるのは 210kt 以下。速いと「速度が速くILSに乗れません」と出る。進入許可を受けた機体は滑走路から 25NM 以内で自分で 210kt まで落とす
- ILS 上では `S 160` のように 5NM までの速度 (140〜210kt) を指示でき、前後の間隔調整に使える (「SPEED 160 UNTIL 5 MILES」)。5NM からは進入速度 145kt へ減速
- 3NM で 170kt を超えていると不安定進入として自動で復行

### 機体一覧の ! マーク

右上の機体一覧で、放っておくとまずい機体に印が付きます (理由は一覧の下段に表示)。

- `!` (黄): 着陸・ハンドオフまでの指示が足りない
  - 到着機: 進入許可 (ILS) が出ていない (待機中を含む)
  - 到着機: 進入許可なしで FAF から 15NM 以内にいるのに 210kt を超えていて、減速の指示もない (「速度が速い」。データブロックの速度もオレンジになる)
  - 出発機: 出口 Fix への経路がない、または出口高度以上の高度を指示していない
- `!!` (赤): 今の進路のままだと 2 分以内に空域外へ出る

### 得点

- 着陸 / ハンドオフ: +100
- 航跡ボーナス: 最大 +50。点線の標準経路 (STAR / SID 相当) に近く飛ばせた割合で決まります
- 間隔欠如 (水平 3NM かつ垂直 1000ft 未満): -30
- 空域外への逸脱: -100
- 衝突: ゲーム終了

## マップデータについて

関東マップの Fix・無線施設 (約90か所) と STAR / SID は、AIP Japan (AIRAC 2026-01) から取った実データです。
データの扱いは末尾の「ライセンスとデータについて」を見てください。

- 到着: 羽田は STONE (北) と ADDUM (南)、成田は MELON (北東) と VENUS (南) から STAR に入る。到着機はその手前、地図の端に 12000〜14000ft で現れる
- 運用 (開始画面で選択):
  - 北風運用 (年の約6割): 羽田 34L/34R 着陸・05/34R 離陸、成田 34L 着陸・34R 離陸
  - 南風・好天 (LDA): 羽田 22/23 へ LDA 進入・16L/16R 離陸。南風の日のふだんの形
  - 南風・悪天 (ILS): 雲が低い日。STEAM→ILS 22 (FAF NITRO)、NYLON→ILS Z 23 (FAF SALVO)。2本の進入コースが交わるので 22/23 は1列
  - 南風・新経路 (15〜19時): 都心上空から 16L/16R に着陸、22 と 05 から離陸。新経路の Fix の座標は手元の資料にないため、到着経路の後半はゲームの推定
- 計器進入の Fix (BONDO・DAMBO・TAYAS・DOMEL・NITRO・SALVO・成田の COSMO・GREBE など) は、AIP の進入チャートの座標から追加
- 出発: 羽田は PLUTO / SEKID / YANAG / JYOGA / MIURA / KANEK、成田は TETRA / JYOSO / PAPAS / CUPID / BAY の各 SID。出口 Fix を AIP の制限に近い高度以上で通過させるとハンドオフ
- 滑走路の向きは真方位 (例: 羽田34 = 330°)。ゲーム内の方位はすべて真方位です (実際の管制は磁方位で、約7°ずれます)
- SID 途中の一部の RNAV 点 (TT051 など) は座標が取れなかったので省略。滑走路の端点と海岸線はおおよそです
- 実際の運航には使えません

1機あたり実時間で15〜30分ほどかかるので、上部の 4倍速 / 8倍速 も使ってください。
書式は `js/data/kanto.js` の冒頭のコメントにあります。

### 中部 (セントレア・小牧・静岡)

`js/data/chubu.js`。セントレアの進入管制に、小牧・静岡の出入りと、中部上空を通る航空路 (東京〜関西・福岡) の一部を加えた範囲です (京都の手前〜駿河湾・伊豆西岸)。

- 運用: 北風 (セントレア RWY36・小牧 34・静岡 30) / 南風 (RWY18・16・12)
- セントレア: AIP の RNAV Fix 30か所と CHUBU VOR (CBE)。STAR は SOUTH ARRIVAL (→ RWY36 の PROBE) / NORTH ARRIVAL (→ RWY18 の QUEST)、入口は CARDS・CHESS・SWING・SLIDE・DARTS。SID は CHITA (実データ)・OUMI・MEIJYO・TOYOTA。滑走路は実在の PROBE と QUEST を結ぶ線から真方位 349°
- 小牧: NAGOYA VORTAC (KCC)・KOWA VORTAC (XMC)・TALMI・HEIAN は AIP の座標。STAR は EXPOH (XMC または SWING から)、SID は TALMI (→ HEIAN)・HOUBA・MORIZ
- 静岡: SHIZUOKA VOR (SZE)。STAR は ENSYU / BAIKU (→ SUZKI → OHCHA)、SID は UNODA と CHAUS
- **上空通過機** (緑): 空域を横切るだけの機体。データブロック右下の出口 Fix を、表示の高度の範囲で通過させると次の管制へ引き継ぎ (+100、航跡ボーナスあり)。上部の ⇄ が引き継いだ数
  - ITAMI: 東京方面 → 伊丹・関西。FL200〜220 で入ってきて、HEIAN を 9000〜13000ft で (降下させる必要がある)
  - KANTO: 関西 → 東京方面。13000〜15000ft で入ってきて、HOUBA を 17000ft 以上で (上昇させる必要がある)
  - EAST / WEST: 福岡・那覇方面と東京の間を、南側の FL210〜240 で横切る
- Fix の位置の求め方: CHAUS (CBE R067 × SZE R356)・HIKNE (CBE R314 × CUE R060)・MORIZ (KCC R137 × XMC R039) は、AIP の「〇〇から何度」の記述 2本の**交点**から計算。EXPOH・HOUBA・OHCHA・SUZKI・UNODA は方位と距離からの**推定**

### 中国・四国 (広島・岡山・高松・松山・高知)

`js/data/okayama.js`。瀬戸内海を中心に、5つの空港 (どれも滑走路1本で、到着と出発が同じ滑走路) と、上空を抜けていく機体を扱います。

- 運用: 東寄りの風 (広島10・岡山07・高松08・松山14・高知14) / 西寄りの風 (28・25・26・32・32)
- AIP から取れたもの:
  - 広島: STAR (MISEN・VISTA)、RNAV SID (KIJYY・MOMOT・SINFO)、HONGO VOR/DME (HGE)、ILS の FAF
  - 高松: OLIVE RNAV ARRIVAL、KAGAWA VOR/DME (KTE)・SHODO VOR/DME (STE)
  - 松山: EAST / WEST RNAV ARRIVAL、MATSUYAMA VOR/DME (MPE)・KUGA VORTAC (IWC)
  - 高知: STAR (POPPY・PANCH・OKITU・KABIL → ANPAN)、RNAV SID (KARIN・KAIFU・MUROT・OMOGO)、KOCHI VOR/DME (KRE)
  - 岡山: 滑走路、KIBI VOR/DME (OYE)・OKAYAMA VORTAC (OKC)、SID の道筋
- **推定**のもの:
  - 岡山の CHIZU・WASYU・SAYOH・TAMBA (AIP の方位・距離の記述から)、有視界の位置通報点 (地名の位置から)
  - 高松・松山の SID の出口 (座標表が資料になかったため、近くの既知の Fix)
  - 上空通過機の経路 (福岡・那覇方面と関西・東京方面を結ぶ瀬戸内の流れを、無線施設を結んだ線で表したもの)。東行き FL210/230、西行き FL220/240
  - 滑走路の向き (広島は ILS 10/28 の FAF を結ぶ線、ほかは STAR の最後の Fix から逆算)
- 実際には ILS がない向きもありますが (岡山25 など)、ゲームではどれも `ILS 25` のように進入許可を出せます

### 最終進入へのつなぎ方 (全マップ共通)

経路の最後の Fix から最終進入へは自動でつなぎます。Fix が FAF の後ろ (進入方向から ±45° 以内) にあれば FAF へまっすぐ、滑走路の横や手前で終わる経路なら、来た側の基点 (`07 BASE` など、FAF の 3NM 外側で最終進入コースから 4NM 横) を経由して浅い角度で FAF へ入ります (ダウンウインド → ベース → 最終進入)。

### マップの追加

関西などを追加するときは `js/data/kansai.js` などを同じ形式で作り、`index.html` に `<script>` を1行足し、`js/app.js` の `MAPS` に地域を登録すればタイトル画面で選べるようになります
(`kansai` は登録済み)。滑走路運用の選択肢は各マップの `configs` から自動で作られます。
